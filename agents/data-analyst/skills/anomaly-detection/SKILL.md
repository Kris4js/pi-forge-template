# 异常检测

## 检测目标

1. **发现值得关注的波动**：从大量门店/渠道/品类中筛选出真正需要人工关注的对象，而不是把所有波动都罗列出来
2. **区分异常类型**：异常下滑、异常增长、断崖式归零（疑似闭店/系统停传）需要用不同的语气和优先级呈现
3. **给出初步线索**：不止告诉"谁异常了"，还要给出"可能和什么有关"的初步方向，为后续归因分析铺路
4. **控制信息密度**：避免因为过度敏感的阈值导致报表被大量低价值异常淹没

## 处理约束

- **不脱离数据质量检测独立运行**：进入本技能前应已完成数据质量检测，"待复核"的极值要先排除数据问题
- **不用波动率单独下结论**：小基数对象的高波动率不代表真实经营问题，必须结合绝对金额影响一起判断
- **不把归因塞进异常检测的结论里**：只给"初步线索"，不做确定性归因，确定性归因交给归因分析技能，且要有数据支撑
- **断崖异常必须置顶**：即使数量少，也不能被"影响金额不是最大"这类排序逻辑埋没，因为很可能是闭店/掉线，业务上最紧急

## 最佳实践

### 先选对比基准，再算波动
按分析粒度（门店/渠道/品类/客户）明确用环比上月、同比去年同期，还是对同类目标均值作为基准，并在结论中说明用的是哪种基准，避免"波动很大"这种脱离参照系的模糊表述。

### 算完波动率要过一遍业务量级
(当前值 − 基准值) / 基准值 算出来之后，先剔除基数过小、绝对影响可忽略的对象，例如月销售额不足 5 万的门店波动 100% 也不重点呈现，否则报表会被大量"数字上吓人、业务上无所谓"的噪音淹没。

### 三种异常类型分开呈现
异常下滑、异常增长、断崖式归零性质完全不同，断崖异常（此前稳定、突然连续归零）优先级最高，很可能是闭店或数据接入中断而非经营问题，需要单独强调而不是混在下滑列表里。

### 给出线索但不下定论
如果异常门店所在渠道整体也在下滑，标注"可能受渠道大盘影响"，与门店自身问题区分开，避免把大盘性下滑误判为个体经营问题——这个区分对后续归因分析很关键。

## 判断标准

| 类型 | 阈值 | 优先级 |
|---|---|---|
| 断崖异常 | 连续 2 个统计周期为 0（此前有稳定记录） | 最高，单独强调 |
| 高影响异常 | 波动幅度 > ±30% 且绝对金额影响 > 大盘 0.5% | 高 |
| 低置信度异常 | 波动超阈值但样本量低于最小交易笔数 | 降级展示，加注说明 |

## 输出格式

```
### 异常清单（按优先级排序）
1. [断崖异常] 对象名称 | 当前值 | 基准值 | 波动幅度 | 建议关注等级：紧急
2. [高影响下滑] ...
3. [高影响增长] ...
4. [低置信度] ...（可折叠或归入"其他"汇总）

其他 N 家门店波动在正常范围内，未列出。
```

## 示例

### 示例 A：断崖式归零

**场景**：某门店此前月均销售额稳定在 18 万左右，最近连续 2 个月为 0。

**输出示例**：
> [断崖异常｜紧急] XX 建材市场店：连续 2 个月销售额为 0，此前月均 18 万元。极可能为闭店或数据接入中断，而非真实经营下滑，建议优先核实门店经营状态而非做经营层面归因。

### 示例 B：渠道大盘性下滑而非个体问题

**场景**：某门店销售额环比下滑 35%，同时其所在的抖音渠道整体环比下滑 28%。

**输出示例**：
> [高影响下滑] XX 旗舰店：环比下滑 35%，影响金额占大盘 0.8%。初步线索：所在抖音渠道整体环比下滑 28%，该门店下滑幅度接近渠道大盘水平，可能主要受渠道大盘影响而非门店自身问题，建议归因分析时优先核查渠道层面因素。
