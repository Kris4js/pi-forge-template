# 归因分析

## 分析目标

1. **区分确定性结论和推测**：数据能直接支撑的原因和基于经验的猜测，必须在表述上明确区分
2. **不穷举，只呈现主因**：从候选因素里挑出 1-2 个真正被数据支撑的主因，而不是把所有可能性都罗列一遍
3. **诚实面对"归因失败"**：数据不足以支撑任何明确归因时，直接说明，不能编造

## 处理约束

- **不允许把推测包装成确定性结论**：低置信度的内容必须带"可能""推测"等措辞
- **不允许编造归因**：找不到吻合的候选因素时，输出"暂无法归因"而不是硬凑一个听起来合理的原因
- **不允许省略置信度标签**：即使结论会被下游的叙事报告 Agent 简化使用，置信度标签也不能被去掉

## 最佳实践

### 内部因素优先于外部因素
候选归因维度里，价格变动、促销活动、上架/下架 SKU、渠道政策调整这类内部因素优先排查，因为数据里能直接验证；大盘季节性、竞品动作、平台规则变化这类外部因素往往缺乏数据支撑，只能作为推测补充，且要默认标注为推测。

### 用时间点吻合做相关性初筛
候选因素发生变化的时间点是否与指标波动时间点吻合，是判断是否可以归因的第一道筛选，时间点对不上的候选因素直接排除，不需要进一步论证。

### 只呈现被数据支撑的 1-2 个主因
不要把所有筛出来的候选因素都罗列给用户，结合业务常识排序后，只呈现真正有说服力的 1-2 个主因，穷举式的罗列会让结论显得不负责任、缺乏判断力。

### 找不到原因时不要硬编
如果数据无法支撑任何明确归因，直接说明"暂无法定位具体原因"，并给出后续排查建议，比如需要补充哪个维度的数据才能进一步验证，这比给出一个不可靠的归因更有价值。

## 判断标准

| 情况 | 判定 | 表述要求 |
|---|---|---|
| 时间点吻合 + 有直接数据支撑 | 高置信度归因 | 可直接表述 |
| 仅有时间相关性、无直接因果数据 | 低置信度推测 | 必须带"可能/推测"措辞 |
| 无任何吻合因素 | 暂无法归因 | 输出"暂无法归因"+ 后续建议 |

## 输出格式

```
### 归因结论
[高置信度归因]：结论 + 支撑数据

[补充推测]（如有）：内容 + 置信度标签

后续建议：（如需要补充数据或进一步排查的方向）
```

## 示例

### 示例 A：高置信度归因（促销活动）

**场景**：某门店销售额环比增长 45%，增长时间点与该门店参与的平台大促活动时间完全吻合。

**输出示例**：
> [高置信度归因] XX 门店销售额环比增长 45%，与该门店 6 月 18 日至 20 日参与平台大促活动的时间完全吻合，活动期间日均销售额是平时的 3.2 倍。判断该增长主要由大促活动拉动。

### 示例 B：低置信度推测 + 归因失败提示

**场景**：某品类整体环比下滑 12%，未发现价格、促销、上下架等内部因素变化，怀疑与季节性有关但无法验证。

**输出示例**：
> 当前数据未发现价格调整、促销变化、SKU 上下架等内部因素与该品类下滑时间点吻合。[低置信度推测] 该品类在往年同期也存在季节性回落规律，可能与季节性因素有关，但当前数据无法直接验证。如需确认，建议补充去年同期数据做同比验证，或核查是否存在未被记录的竞品促销活动。
