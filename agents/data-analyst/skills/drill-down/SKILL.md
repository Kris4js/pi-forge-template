# 下钻分析

## 分析目标

1. **定位主要贡献项**：不是简单罗列子项数据，而是算清楚每个子项对总体波动"贡献了多少"
2. **判断是否需要继续下钻**：贡献是否集中决定了要不要往更细的维度继续拆
3. **保留可追溯路径**：下钻过程要能被复现和继续交互，而不是一次性算完就丢弃中间结果

## 处理约束

- **不脱离贡献度只看子项自身涨跌**：子项自己跌了 50% 不代表它是主要拖累项，如果它占比很小，贡献度可能可以忽略
- **不无限下钻**：超过 3 层（如渠道→品类→门店）信息密度过高，不适合在自动生成报表里直接摊开，应转成"点击查看明细"的交互
- **贡献度分散时不能强行归因到单一对象**：如果没有明显的主要拉动项，就应该老实说"普遍性波动"，不要为了给结论硬挑一个"背锅"对象

## 最佳实践

### 按业务层级顺序展开，不要一次全打开
下钻路径应遵循业务常见的维度层级顺序，例如：总销售额 → 分渠道 → 分品类 → 分门店，一层一层拆，而不是把所有维度组合都算一遍甩给用户自己找规律。

### 算贡献度而不是同比环比
子项对总体波动的贡献度 = 子项变化量 / 总体变化量，这才是回答"是谁拉低了大盘"的正确指标，子项自身的同比环比只能说明它自己涨跌多少，不能直接说明它对大盘的影响力。

### 用贡献度集中度决定要不要继续拆
单一子项贡献度过高时（见判断标准），说明问题比较集中，值得继续往下一层定位到具体门店或 SKU；贡献度分散时继续下钻的边际价值很低，应该在当前层级给结论。

## 判断标准

| 情况 | 阈值 | 结论方向 |
|---|---|---|
| 主要驱动因素 | 单一子项贡献度 > 50% | 继续下钻一层定位具体原因 |
| 普遍性波动 | 最大子项贡献度 < 25% | 描述为"多渠道/多门店普遍性小幅波动"，不归因到单一对象 |
| 下钻深度上限 | 超过 3 层 | 转为可交互明细，不在报表中直接展示 |

## 输出格式

```
### 下钻结论
总体：XX 指标环比下滑 N%

贡献度拆解（第一层：渠道）
- 渠道 A：贡献 X%（绝对金额 Y）
- 渠道 B：贡献 X%
- ...

判断：[单一驱动 / 普遍性波动]
建议下一步：[继续下钻至品类层级 / 无需继续下钻]
```

## 示例

### 示例 A：单一渠道主导下滑，建议继续下钻

**场景**：总销售额环比下滑 8%，京东渠道贡献了下滑量的 72%。

**输出示例**：
> 总销售额环比下滑 8%（约 5,600 万元）。贡献度拆解：京东渠道贡献了 72% 的下滑量（约 4,000 万元），天猫贡献 15%，抖音、拼多多合计贡献 13%。京东渠道贡献度过于集中，建议继续下钻至京东内部的品类/门店层级，定位是整体性下滑还是个别品类/门店拖累。

### 示例 B：普遍性波动，不强行归因

**场景**：总销售额环比下滑 3%，四个渠道贡献度分别为 30%、28%、24%、18%。

**输出示例**：
> 总销售额环比下滑 3%。四个渠道贡献度较为均匀（30%/28%/24%/18%），没有单一渠道占据主导。判断为普遍性小幅波动，可能与季节性大盘因素有关，不建议归因到某个具体渠道，如需进一步排查建议结合归因分析技能核查是否存在共性的外部因素（如大盘季节性）。
